Stress engine code flow

The engine projects stage migration, PD, LGD, EAD and provisions for the synthetic €11bn EUR, amortised-cost book over 2027–2029, baseline and adverse. The code has two separate parts that share no code. One-off steps build the synthetic starting point and the test material once. The run pipeline is the engine. It ingests an input set and builds each facility's contractual cash flows from balance, interest rate and maturity. One Z-score per segment and year moves the TTC rating matrix, the TTC LGD and the prepayment rate with the economy. EAD per default date is the contractual balance after prepayment. Rating grades then decide stages, and the run projects and reports provisions.

Part 2 · Every runThe run pipeline

$ stress run --inputs inputs/<hash> --scenarios baseline,adverse --variant core

One command runs both scenarios through the same code. R5 does not depend on the scenario, so it runs once per facility and serves both. Baseline parameters are built before adverse, because adverse buckets after 2029 revert toward baseline 2029. The two result sets are kept apart and never blended (REG-07). A sensitivity such as the AT-35 utilisation case runs as a separate --variant, with its own label.

Inside R5Where cash flows are generated

R5 is the only step that creates cash flows, and they are contractual. It needs three facts per facility: drawn balance, interest rate and maturity, plus the repayment profile that splits each payment into interest and principal. Prepayment, default and drawdown depend on the scenario, so R6 applies them. The schedule is the same in both scenarios, so it is built once.

Inside R6Prepayment and EAD

EAD is computed in R6 because prepayment depends on the scenario. R6 takes the contractual balance from R5, removes the expected prepayments and adds the converted undrawn amount. Prepayment is applied here once and nowhere else.

R6 · prepayment rate

Moves with Z, like PD and LGD

CPR[t] = Φ( Φ⁻¹(CPR_TTC) + v × Z[t] )
SP[k] = (1 − CPR[1]) × … × (1 − CPR[k−1])

SP[k] is the share of the drawn balance not yet prepaid at default date k, and SP[1] = 1. With v > 0, prepayment falls when the economy worsens; v = 0 keeps the TTC rate. CPR_TTC and v are set per segment (D14).

R6 · EAD per default date

Contractual balance after prepayment

EAD_drawn[k] = B[k] × SP[k]
EAD_undrawn[k] = U[k] × CCF
EAD[k] = EAD_drawn[k] + EAD_undrawn[k]

B[k] comes from R5, and all three amounts are stored (EAD-02). The undrawn part is not prepaid. The drawn part feeds the on-balance allowance and the undrawn part the off-balance provision (AT-34). The default survival S[k] in the PD curve leaves prepayment out, so it is never counted twice.

R7 · balance sheet stays static

Prepayment shortens the loss profile, not the stock

GCA stock(y) = GCA stock(2026)

Prepaid and matured balances are replaced like for like in the balance-sheet stock (EXP-01). Prepayment only changes the EAD profile used to measure loss (EAD-05). At each year-end, R6 restarts the profile from the static stock balance.

Inside R4, R6 and R7TTC PD matrix and how stages follow from it

Each segment has a through-the-cycle rating transition matrix on one master scale: N performing grades plus default D. Every performing facility has a current grade and an origination grade. A single matrix drives PD, rating migration and stage migration. As a result the three are consistent by construction, which is what MIG-04 and PD-05 ask for.

R4 · economy → Z

One Z per segment, country, year

Z = Σ β_i × (x_i − μ_i) ÷ σ_i

The x values are the scenario drivers for that segment, such as GDP growth, unemployment and property price change. A positive Z means a better economy than average. The same Z shifts the PD matrix, the LGD and the prepayment rate. After 2029, Z follows the terminal rule (D5).

R6 · TTC matrix → PiT matrix M(y)

Shift each row with Z

C(i,j) = P(end in grade j or worse | start in i)
C_PiT = Φ( (Φ⁻¹(C_TTC) − √ρ × Z) ÷ √(1 − ρ) )
M(i,j) = C_PiT(i,j) − C_PiT(i,j+1)

A worse economy (Z < 0) moves probability toward worse grades and default. Every shifted row still sums to 1. The D column of M(y) is each grade's PD for year y. Each segment has its own ρ (D13).

R6 · PD curve of a grade

Products of future matrices

F[k] = ( e_g × M(y+1) × … × M(y+k) )[D]
m[k] = F[k] − F[k−1], S[k] = 1 − F[k]

This is the lifetime PD of a slice at grade g, under the scenario's own future matrices (perfect foresight, ECL-06). It allows for rating migration on the way to default. The PD-03 identities are checked on every curve. Curves hold whole years only; R8 takes the part of a final bucket that the maturity covers.

R7 · stage of a slice

Stage comes from the grade

S3 if grade = D
S2 if PDlife(g) ≥ k × PDlife(g0)
S1 otherwise

Both lifetime PDs come from the TTC matrix over the same remaining horizon (PD-06), so the line stays fixed per facility. k is a test convention per segment (MIG-05). A slice returns to S1 when its grade improves back over the line. D never cures.

Inside R6 and R8LGD from TTC and the Z-score

Each exposure carries a through-the-cycle LGD. The same Z that shifts the PD matrix moves it with the economy. No collateral, guarantee or recovery data is needed.

R6 · TTC → LGD of the year

Shift the TTC LGD with Z

LGD[k] = Φ( Φ⁻¹(LGD_TTC) − w × Z[k] )

Z = 0 gives back LGD_TTC. A worse economy (Z < 0) raises LGD, and the result always stays between 0 and 1 without a cap. An LGD_TTC of exactly 0 or 1 passes through unchanged. Each segment has its own w ≥ 0.

R8 · where it is used

The same LGD everywhere

  • S1 and S2 grades: m[k] · EAD[k] · LGD[k] · DF[k]
  • New S3: flow × LGD of the default year
  • Original S3: max(GCA × LGD of the year, prior allowance)

To agreeDecisions to agree before the build

These points are open, and each one changes code. Each has a proposal. Reply with the D number and "agree" or your change.

  1. D1

    How finely to project

    One row per facility and slice: one slice for each performing grade, plus original S3 and each new S3 cohort. Stage is derived from the grade (D2).

    AT-18 needs no-release checked for each exposure, and RPT-06 sums ECL from facility results. 10,000 facilities × (N grades + up to 4 S3 cohorts) × 3 years × 2 scenarios is still small.

    R7R8
  2. D2

    SICR rule

    A performing slice is S2 when its lifetime PD is at least k times the lifetime PD at the facility's origination grade. Both come from the TTC matrix over the same remaining horizon. k is set per segment and labelled a test convention; you supply it. A slice returns to S1 when its grade improves back over the line.

    PD-06 asks for a lifetime comparison with origination, and MIG-05 for a labelled synthetic threshold. Basing the line on TTC keeps it fixed per facility, so only rating moves change stage. A PiT-based line would also move S2 volumes with the economy.

    R7parameter_set
  3. D3

    Opening grades

    The generator gives each facility an origination grade and a current grade. They are chosen so that the stage rule gives back the facility's §5.2 opening stage, and so that each segment's S1 and S2 average PD matches §8.7. Qualitative S2 triggers (30+ DPD, watchlist, forbearance) are not used.

    Then grade and stage never conflict (DAT-04), and R3 can block any facility whose stage the rule cannot explain.

    O3R3
  4. D4

    Z-score LGD: formula and coefficients

    LGD[k] = Φ(Φ⁻¹(LGD_TTC) − w × Z[k]), with Z = Σ β_i × (x_i − μ_i) ÷ σ_i by segment and country. The β, μ, σ and w values are synthetic, sit in the parameter set, and you supply them.

    This form gives back the TTC value when Z = 0, stays between 0 and 1 without a cap, and rises as the economy worsens (LGD-08, LGD-11).

    R4R6
  5. D5

    Parameters after 2029

    Adverse Z reverts linearly to baseline 2029 over 2030–2035 (weights 5/6 down to 0), and baseline stays flat. The PiT matrices and LGD follow from the reverted Z. S1 at end-2029 interpolates the loss rate (AT-06). S2 lifetime uses the reverted matrices and LGD.

    AT-06 pins only the first year. ECL-05 says interpolating the loss rate and interpolating its drivers can give different answers, so the S2 choice needs your sign-off.

    R4R6R8
  6. D6

    S3 allowance

    Original S3: max(GCA × LGD of the year, prior allowance), checked per exposure. New S3: flow × LGD of the default year, booked once and floored after that. LGD comes from the same TTC and Z rule.

    There are no recovery schedules, so S3 uses the same LGD as S1 and S2. AT-03 and AT-04 cover S3.

    R8
  7. D7

    Maturity and replacement

    A facility that matures before end-2029 is replaced like for like. The replacement has the same segment, the same current and origination grade (and so the same stage), the same country, and the starting residual maturity. It restarts its cash-flow schedule. GCA does not run off.

    P02, P03, P05 and P06 contain 1-year maturities, so this case occurs in the generated books (EXP-01, EAD-05).

    R5R7
  8. D8

    Opening allowances

    Calculated inside the one-off generator with its own formula. It uses PD curves from the TTC matrix (Z = 0), TTC LGD, the TTC prepayment rate, and a bullet schedule at the facility's rate and maturity. S3 is GCA × TTC LGD. Delivered as the opening_provisions dataset. The run takes them as given and never recomputes them.

    §5.2 asks for allowances that are calculated consistently and then frozen. This keeps Part 1 independent of the engine. Any mismatch with the engine's own formula shows up as a large first-year charge in the R9 report.

    O4
  9. D9

    Where v1 stops

    Synthetic mode only. Regulatory mode is a guard that blocks the run. ECB benchmarks, sovereign routing and the MOD-03 coverage test are not built. POCI and central-bank exposures are not in v1 data. Full credit REA, template mappings and §11.2 country selection are out, and REA floors exist as kernels only.

    R1R10
  10. D10

    Stack and file formats

    Python 3.12, uv, pytest, ruff, numpy and pandas (with scipy for Φ). Input tables, matrices and the cash-flow schedule in Parquet. Scenarios and parameter set in YAML so diffs stay readable. float64, unrounded until output.

    The tightest tolerance is 1e-10 on rates, and float64 meets it. Decimal is not needed.

    all
  11. D11

    Does Z also drive PD?

    Yes, through the matrix (D13). One Z per segment, country and year shifts both the TTC matrix and the TTC LGD, so PD and LGD move together.

    A TTC matrix needs a PiT conversion. Reusing the LGD's Z keeps one economic driver for the whole engine.

    R4R6
  12. D12

    Repayment profile and contractual balance

    Each facility has a profile: bullet, annuity or linear. The core run uses bullet for every facility, and annuity and linear run as a separate variant. B[k] is the contractual drawn balance at the default date, before that date's payment. Floating-rate loans keep their current rate in v1. R5 does not compute EAD; R6 builds it from B[k] (D14).

    Building cash flows from balance, rate and maturity needs a rule for principal. Bullet keeps the contractual balance flat, as in the acceptance cases.

    R5facilities
  13. D13

    TTC matrix: shape and Z shift

    One TTC matrix per reference segment (7) on a shared master scale of N performing grades plus D, built once in O2. Each row shifts with C_PiT = Φ((Φ⁻¹(C_TTC) − √ρ × Z) ÷ √(1 − ρ)), with ρ per segment in the parameter set. You choose N and ρ.

    This is the standard one-factor form: every shifted row is still a valid distribution, and default moves together with rating migration. Z = 0 gives the median year, a little below the TTC average. If Z = 0 should give back the TTC matrix exactly, as the LGD rule does, drop the √(1 − ρ) divisor.

    O2R6
  14. D14

    Prepayment

    An annual prepayment rate per segment, CPR[t] = Φ(Φ⁻¹(CPR_TTC) + v × Z[t]), with CPR_TTC and v ≥ 0 in the parameter set; you supply them. It reduces only the drawn balance: EAD_drawn[k] = B[k] × SP[k]. Prepayment during a year lowers EAD from the next year's bucket on, so SP[1] = 1, which is the conservative choice. It is applied once, in EAD, and never also in the default survival. Acceptance cases use zero prepayment.
