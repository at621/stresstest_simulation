From a portfolio to a sealed result

One real run, followed step by step: which portfolios it uses, how each one gets its macro model, what the engine then does, and what comes out. Every figure, file name and error message below comes from that run or from a deliberate test of it.

The book is synthetic, and the coefficients, external scores and energy prices are invented for this example. The page shows how the engine behaves. It says nothing about what an energy crisis would really cost.

Step 1Start from the book

The current input set is d62d0386f2c5256e: six portfolios with €11.0bn of GCA and €2.0bn undrawn, across DE, ES, FR, IT, NL and PL.

A portfolio is a reporting label. A segment is the unit the engine calculates on: it has its own TTC matrix, parameters and macro model. Five portfolios have one segment each. P06 has two.

The base scenarios are baseline and adverse, each with five variables for 2027–2029: gdp_growth, unemployment, residential_price_change, cre_price_change and reference_rate. Every country has the same path today, so Z does not yet differ by country.

The carve-out in this example

# In the specification file
assignments:
  - where: {portfolio: P05, nace_code: D}
    segment: P05_ENERGY
    portfolio: P07
  • The selector catches 136 facilities: €800m of GCA and €252.8m undrawn.
  • P05 falls to 664 facilities and €3,200m. P07 starts at €800m.
  • A selector can match on facility_id, portfolio, segment, country or nace_code. Every condition must hold.
  • The portfolio line here is what moves the facilities. The portfolio field under segments is only a description.

Adding a portfolio with its own data

  1. Copy the seven input files to a working folder and add the new book: rows in facilities, obligors, opening_provisions and, for undrawn limits, commitments, matrix rows in ttc_pd_matrix, and a segment entry in parameter_set.yaml.
  2. Freeze the folder: uv run python -m foundation.synth package --source <prepared-directory> --out inputs. This writes the hashes and control totals and records pending owner approval. It does not generate loans or estimate provisions.
  3. In your file, set input_set_hash to the full hash in the new manifest.json, and run.inputs to the new folder.
  4. Give the new segment a template_class, and a model if it needs one.

The review tested this with a seventh portfolio. P01–P06 baseline and adverse charges matched the control run to €0.01m.

Step 3Link the models

A link takes two parts: a definition under models, and one line under segments. The figure shows how each facility reaches its Z in this example.

The three model kinds, as used here

linear for P05_ENERGY

Use for a standard regression. Z is the sum of β × (x − mean) / sd.

models:
  energy_sector:
    kind: linear
    source: "Illustrative coefficients"
    version: walkthrough-v1
    drivers:
      gdp_growth: {beta: 0.5, mean: 0.015, sd: 0.03}
      energy_price_change: {beta: -0.5, mean: 0.03, sd: 0.15}

polynomial for P02

Use for curvature or lags. Each term can set lag and power (1, 2 or 3), and the model can add an intercept.

models:
  consumer_nonlinear:
    kind: polynomial
    source: "Illustrative coefficients"
    version: walkthrough-v1
    terms:
      activity: {variable: gdp_growth, mean: 0.02, sd: 0.03, beta: 0.6}
      activity_squared: {variable: gdp_growth, mean: 0.02, sd: 0.03, beta: -0.08, power: 2}
      unemployment: {variable: unemployment, mean: 0.07, sd: 0.025, beta: -0.3}

supplied for P04

Use when Z comes from an external model. You give one row per scenario, country and year.

models:
  cre_external:
    kind: supplied
    source: "Illustrative scores standing in for an external CRE model"
    version: walkthrough-v1
    values:
        - {scenario: baseline, country: DE, year: 2027, z: 0.00}
        - {scenario: baseline, country: ES, year: 2027, z: 0.00}
        # ... 54 rows in all: 3 scenarios, 6 countries, 3 years

The link itself

segments:
  P02:
    macro_model: consumer_nonlinear
  P04:
    macro_model: cre_external
  P05_ENERGY:
    inherits: P05
    portfolio: P07
    macro_model: energy_sector
    template_class: "Loans and advances - NFC - Energy sector (walkthrough label)"
  • A model can serve several segments: name it under each.
  • A link replaces the segment's Z only. Its matrix, rho, sicr_k, lgd_w and prepayment settings stay, unless you override them here.
  • One Z drives PD, LGD and prepayment together. You cannot give PD one model and LGD another.
  • A defined model with no segment stops the run, and so does a link to a model that is not defined.
  • A new segment in a static run needs a template_class.

Step 4Give the models their data

Every model needs a path for every variable it reads, in every scenario you run. This example adds one scenario and one new variable.

A new scenario

scenarios:
  energy_crisis:
    inherits: adverse
    narrative: "Energy shock: deeper recession and higher rates than adverse."
    overrides:
      - {variable: gdp_growth, country: '*', year: 2027, value: -0.08, unit: decimal, value_type: growth}
      - {variable: gdp_growth, country: '*', year: 2028, value: -0.04, unit: decimal, value_type: growth}
      - {variable: reference_rate, country: '*', year: 2027, value: 0.06, unit: decimal, value_type: level}
  • inherits copies every adverse value. overrides replace only the cells named.
  • country: '*' means all six countries. For one country, name it. You cannot use '*' and a single country on the same cell.
  • You can also write a full path with values and no parent.
  • Names are permanent: reusing adverse stops the run.

A new driver

additional_values:
  - {scenario: baseline, country: '*', variable: energy_price_change, year: 2027, value: 0.03, unit: decimal, value_type: growth}
  - {scenario: adverse, country: '*', variable: energy_price_change, year: 2027, value: 0.10, unit: decimal, value_type: growth}
  - {scenario: energy_crisis, country: '*', variable: energy_price_change, year: 2027, value: 0.60, unit: decimal, value_type: growth}
  # ... 9 rows in all: 3 scenarios, 3 years
  • Baseline and adverse need the new variable too, or R4 stops with MISSING_SCENARIO_VALUE.
  • additional_values can add values but never overwrite one.
  • A term with lag: 1 also needs a 2026 value. The engine does not interpolate or fill gaps.

How the crisis fades

terminal_policies:
  energy_crisis: {method: reversion, years: 3}
  • Past 2029, Z moves back to the baseline's 2029 level. The base rule takes 6 years. This policy takes 3.
  • method: flat holds the 2029 Z instead. Baseline always stays flat.

Step 9Check, compare and replay

  1. Confirm each link. Open macro_models.csv. Each segment should show the model you intended.
  2. Compare with the last run. Unlinked portfolios should not move.
  3. Replay it. The rerun reads the sealed copies, so the original files are no longer needed.
  4. Read the open gates. A sealed run is a result. It is not an approval.
  5. To change anything, write a new version. Edit the file, change version and run again. Sealed runs are never edited.

OptionalLet the balance sheet change

The runs above keep the book static, as the EBA method does. To test a changing book, add one setting and a complete grid of volume rates. Treat the result as an internal sensitivity.

run:
  balance_sheet: dynamic

balance_sheet:
  assumptions:
    - {scenario: baseline, year: 2027, portfolio: P01, drawn_change: 0.0, undrawn_change: 0.0}
    - {scenario: adverse, year: 2027, portfolio: P01, drawn_change: -0.03, undrawn_change: 0.1}
    - {scenario: energy_crisis, year: 2027, portfolio: P01, drawn_change: -0.1, undrawn_change: 0.1}
    - {scenario: energy_crisis, year: 2027, portfolio: P07, drawn_change: 0.05, undrawn_change: -0.2}
    # ... 63 rows in all: 3 scenarios, 3 years, 7 portfolios
  • Each year, before migration, performing drawn and undrawn balances are multiplied by 1 plus the rate.
  • S3 cohorts and their provisions are never scaled.
  • Portfolios here means reporting portfolios, so P07 needs its own rows. A missing row stops the run.
  • In this example energy firms draw on their lines in the crisis, so P07 drawn rises 5% a year and undrawn falls 20%. Other books shrink 10% a year.
  • The run adds exposure_movements.csv and dynamic_books.csv. It drops static_books.csv and analysis_template_replica.csv.
%%T_DYNAMIC%%

Most books shrink, so total charges fall. P07 goes the other way: its crisis charge rises from €108.1m to €111.5m. In the dynamic run P07 reached €909.5m rather than €926.1m (€800m × 1.05³), because S3 balances are not scaled.

ReferenceWhat this workflow does not do

  • Regulatory use. Files must say SYNTHETIC, and --mode regulatory blocks. Regulatory use still needs the final EBA package, official inputs, validated models and owner sign-off.
  • Model estimation. The engine runs the coefficients it is given. It does not estimate, backtest or validate them.
  • Separate models per risk parameter. One Z per segment drives PD, LGD and prepayment.
  • A new matrix for a carve-out. The new segment copies its parent's matrix. A different matrix needs a new input set.
  • A different horizon or grade scale. Horizon, master scale, tolerances and variants stay in the base parameter set. A horizon key in the file blocks.
  • New lending. Volume rates scale existing facilities. There are no fresh vintages, sales, write-offs or cures, and new product types need code.
  • Charges by country. A country crisis shows in Z, stocks and provisions. No report gives the charge by country.
  • Approval. Approving the base input set does not approve an experiment's scenarios or models.
  • Replay across code changes. A rerun needs the same source and environment. Runs sealed before fe123e5 stop with SOURCE_MISMATCH on main.
